# 슬러지 (Sludge)

## 핵심 정의

> 슬러지는 사람들이 자신에게 이로운 결정을 실행하거나 권리를 행사하는 것을 어렵게 만드는 불필요한 절차적 마찰이다.

* **본질:** 좋은 행동을 쉽게 만드는 넛지의 반대편에서, 행동을 지연시키거나 포기하게 만드는 설계다.
* **맥락:** 해지 절차, 환불, 신청서, 공공 서비스, 개인정보 설정, 구독 관리에서 자주 나타난다.

## 작동 방식

슬러지는 서류, 대기, 반복 입력, 불명확한 안내, 복잡한 화면, 숨겨진 버튼 같은 형태로 나타난다. 각각은 작아 보여도 사용자의 시간, 주의, 인내심을 소모시켜 행동을 포기하게 만든다.

* **메커니즘:** 절차적 마찰 증가 -> 인지 부담과 시간 비용 증가 -> 행동 포기.
* **구체적 예시:** 가입은 한 번 클릭으로 가능하지만 해지는 전화 상담과 긴 절차를 요구하는 구조.
* **연계 프로세스:** 목표 행동 발생 -> 마찰 노출 -> 지연 또는 포기 -> 제공자에게 유리한 상태 유지.

## 실무적 의미

서비스 설계에서는 필요한 보안 절차와 불필요한 슬러지를 구분해야 한다. 사용자의 권리 행사, 환불, 해지, 지원 요청처럼 민감한 흐름일수록 절차의 투명성과 단순성이 중요하다.

* **안정성:** 필요한 검증 절차와 의도적 방해를 분리한다.
* **측정 가능성:** 단계별 이탈률, 소요 시간, 반복 입력 횟수를 본다.
* **데이터 기준:** 사용자가 원하는 행동과 기업이 원하지 않는 행동에서 마찰이 다르게 배치되어 있는지 확인한다.

## 주의할 점

슬러지는 단기 지표를 좋아 보이게 만들 수 있다. 해지를 어렵게 하면 해지율은 낮아질 수 있지만, 장기적으로 신뢰와 브랜드 평판을 손상시킨다.

* **관점의 한계:** 모든 마찰이 나쁜 것은 아니다. 보안과 숙고를 위한 마찰도 있다.
* **상관관계 vs 인과관계:** 낮은 이탈률이 만족 때문인지 절차 장벽 때문인지 구분해야 한다.
