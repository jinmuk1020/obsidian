# 데이터 구조

## 핵심 정의
데이터 구조는 데이터를 저장하고 접근하고 변경하기 위해 조직하는 방식이다. 배열, 리스트, 스택, 큐, 트리, 그래프, 해시 테이블처럼 데이터의 배치와 관계를 정의하는 형식들이 여기에 포함된다.

데이터 구조는 알고리즘과 분리되지 않는다. 같은 문제라도 어떤 구조에 데이터를 담느냐에 따라 탐색, 삽입, 삭제, 정렬, 조회의 비용이 크게 달라진다.

## 작동 방식
데이터 구조는 데이터 사이의 관계와 접근 패턴을 설계한다. 순서대로 접근할 일이 많다면 배열이나 리스트가 적합할 수 있고, 계층 관계를 표현하려면 트리, 복잡한 연결망을 표현하려면 그래프가 적합하다.

좋은 데이터 구조는 필요한 계산을 빠르고 안정적으로 수행하게 만든다. 반대로 문제와 맞지 않는 구조를 선택하면 알고리즘이 단순해도 시간 복잡도나 공간 복잡도가 불필요하게 커진다.

## 실무적 의미
데이터 분석과 머신러닝에서도 데이터 구조는 중요하다. 표 형태 데이터, 희소 행렬, 텐서, 벡터, 인덱스 구조는 처리 속도와 메모리 사용량, 모델 학습 방식에 직접 영향을 준다.

예를 들어 Pandas의 데이터프레임은 표 형태 데이터를 다루기 좋은 구조이고, NumPy 배열은 수치 계산을 빠르게 처리하기 좋은 구조다. 자연어 처리의 단어 임베딩도 텍스트를 벡터 구조로 바꾸는 사례다.

## 주의할 점
가장 복잡한 구조가 항상 좋은 선택은 아니다. 데이터 규모, 접근 패턴, 변경 빈도, 구현 비용을 함께 고려해야 한다. 작고 단순한 문제에서는 단순한 리스트나 딕셔너리가 더 나은 선택일 수 있다.

또한 라이브러리마다 같은 이름의 구조라도 내부 구현과 성능 특성이 다를 수 있다. 실제 병목이 어디서 생기는지 확인하고, 필요할 때만 구조를 바꾸는 것이 좋다.
