# 비동기 I/O 및 동시성 (Concurrency)

## 출처

- Notebook: 내 정수

## 핵심 설명

동시성은 I/O 대기 시간 동안 CPU가 놀지 않고 다른 작업을 수행하게 하여 시스템의 전체적인 처리량을 높이는 기법입니다. asyncio, gevent, tornado와 같은 라이브러리는 이벤트 루프를 활용해 네트워크 요청이나 파일 입출력이 완료되기를 기다리는 유휴 시간을 효율적으로 활용합니다. 이는 연산 속도 자체를 높이는 병렬성과는 다르지만, 수많은 I/O 요청이 발생하는 환경에서 매우 적은 자원으로 고성능을 낼 수 있게 합니다. [20-23]

## 핵심 포인트

- I/O 대기 시간을 활용한 CPU 유휴 시간의 최소화
- 이벤트 루프와 코루틴을 이용한 비블로킹 입출력 관리
- 네트워크 크롤링 및 웹 서버와 같이 I/O 병목이 큰 작업에 특화

## 중요성

하드웨어 성능보다 대기 시간이 지배적인 작업 환경에서 시스템의 효율성과 확장성을 극대화합니다.

### 구체적 메커니즘

비동기 I/O 및 동시성은 프로그램이 I/O 연산이 완료되기를 기다리며 멈춰 있는 대신, 그 시간에 다른 유용한 연산을 수행하도록 설계된 기제입니다 [1]. 핵심 작동 원리는 실행할 함수 목록을 관리하는 '이벤트 루프'를 사용하여, I/O 대기가 발생한 함수의 실행을 중단하고 즉시 다음 작업으로 전환하는 것입니다 [2, 3]. 파이썬에서는 제너레이터를 활용한 '코루틴'을 통해 특정 시점에 실행을 멈추고 제어권을 반환했다가, 데이터가 준비되면 다시 이전 상태부터 재개하는 방식을 취합니다 [4, 5]. 이러한 논블로킹(Non-blocking) 방식은 단일 스레드 내에서도 마치 여러 작업을 동시에 수행하는 것과 같은 효과를 주어 I/O 지연 시간을 효과적으로 감춥니다 [1, 3]. 결과적으로 이는 문맥 전환 비용이 큰 멀티프로세싱의 대안으로, I/O 중심 작업에서 시스템 자원 활용도를 극대화하는 핵심 기술입니다 [2, 6].

### 데이터와 구조

- 지연 시간 지표: 1ms의 네트워크 대기 동안 2.4GHz CPU는 약 240만 개의 명령을 처리 가능함 [7]
- 구현 패러다임 분류: 함수 체이닝을 활용한 '콜백(Callback)'과 미래 결과를 담는 '퓨처(Future)' 방식 [8]
- 주요 라이브러리: gevent(그린렛 사용), tornado(I/O 루프 기반), asyncio(표준 라이브러리) [9-11]
- 최적화 기준: 컨텍스트 전환 비용을 고려하여 실험적으로 도출된 최적 동시 요청 수(사례의 경우 100개) [12, 13]
- 성능 향상 수치: 비동기 방식 적용 시 순차 처리 대비 약 69배의 속도 개선 효과 달성 [14]

### 사례와 적용

- 동시 웹 크롤러: 수백 개의 URL로부터 페이지 콘텐츠를 병렬로 가져와 처리 시간을 수십 배 단축한 사례 [15, 16]
- 비동기 데이터베이스 저장: 소수 판별 결과를 데이터베이스에 기록할 때 발생하는 I/O 병목을 'AsyncBatcher' 일괄 처리를 통해 극복한 장면 [17, 18]
- 고성능 비동기 서버: 페이스북의 tornado 등을 활용하여 다수의 동시 연결을 단일 스레드로 효율적으로 관리하는 서버 구축 [6, 10]
