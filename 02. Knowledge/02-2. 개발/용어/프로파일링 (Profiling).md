# 프로파일링 (Profiling)

## 핵심 정의
프로파일링은 프로그램이 실행되는 동안 시간과 메모리 같은 자원이 어디에서 얼마나 쓰이는지 측정해 병목을 찾는 작업이다. 감으로 최적화하는 대신 실제 실행 데이터를 보고 성능 문제의 위치와 우선순위를 판단하게 해준다.

프로파일링의 목적은 코드를 무조건 빠르게 만드는 것이 아니라, 개선할 가치가 있는 지점을 정확히 찾는 것이다.

## 작동 방식
프로파일러는 함수 호출 횟수, 실행 시간, 누적 시간, 메모리 사용량, 객체 생성량 같은 정보를 수집한다. 개발자는 이 결과를 보고 전체 성능에 큰 영향을 주는 구간을 먼저 확인한다.

예를 들어 어떤 함수가 한 번은 빠르지만 수천 번 호출되어 전체 시간을 잡아먹을 수 있고, 반대로 느린 함수라도 거의 호출되지 않으면 최적화 우선순위가 낮을 수 있다. 프로파일링은 이런 차이를 정량적으로 드러낸다.

## 실무적 의미
프로파일링은 최적화의 출발점이다. 성능 문제가 생겼을 때 코드 전체를 막연히 고치기보다, 실제 병목을 먼저 측정하면 수정 범위를 줄이고 부작용을 낮출 수 있다.

또한 프로파일링 결과는 성능 개선의 근거가 된다. 수정 전후의 실행 시간과 자원 사용량을 비교하면 최적화가 실제로 효과가 있었는지 확인할 수 있다.

## 주의할 점
프로파일링 결과는 실행 환경과 입력 데이터에 따라 달라진다. 작은 테스트 데이터에서 빠른 코드가 실제 운영 데이터에서는 병목이 될 수 있고, 반대로 특수한 상황에서만 느린 코드가 전체 문제처럼 보일 수도 있다.

또한 프로파일링은 설계를 대신하지 않는다. 측정 결과를 바탕으로 병목을 찾되, 가독성이나 유지보수성을 해치면서까지 미세 최적화를 남발하지 않아야 한다.
