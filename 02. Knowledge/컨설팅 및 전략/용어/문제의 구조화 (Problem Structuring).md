# 문제의 구조화 (Problem Structuring)

## 핵심 정의
문제의 구조화는 복잡한 문제를 분석 가능한 하위 질문과 논리적 관계로 나누는 작업이다. 문제를 크게 말하는 단계에서 멈추지 않고, 무엇을 확인하면 답에 가까워지는지 분해하는 과정이다.

## 작동 방식
먼저 해결해야 할 질문을 명확히 정한다. 그다음 질문을 원인, 영향, 선택지, 실행 조건 같은 하위 항목으로 나누고, 중복과 누락이 적은 구조로 배열한다. 이 구조는 분석 계획과 커뮤니케이션의 뼈대가 된다.

컨설팅에서는 로직 트리, 이슈 트리, 가설 기반 분석이 자주 쓰인다. 중요한 것은 도구의 이름이 아니라, 문제를 어떻게 나누면 의사결정에 필요한 증거를 모을 수 있는지다.

## 실무적 의미
문제의 구조화는 분석 시간을 줄이고 팀의 논의를 정렬한다. 각 사람이 다른 질문을 풀고 있으면 보고서는 길어져도 결론은 흐려진다. 구조화가 잘 되면 필요한 데이터, 인터뷰, 분석 산출물이 자연스럽게 정해진다.

## 주의할 점
구조화는 문제를 단순화하지만 현실을 왜곡해서는 안 된다. 너무 예쁘게 나눈 트리는 실제 인과관계를 놓칠 수 있다. 초기 구조는 가설로 두고, 분석이 진행되면 수정해야 한다.
