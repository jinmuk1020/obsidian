# 개념 모델(Conceptual Model)과 시스템 이미지

## 핵심 정의

> 개념 모델은 사용자가 어떤 제품이나 시스템이 어떻게 작동한다고 이해하는 마음속 설명 구조이고, 시스템 이미지는 그 이해를 형성하게 만드는 제품의 겉으로 드러난 단서들이다.

* **본질:** 사용자는 내부 구조를 직접 볼 수 없기 때문에, 버튼, 화면, 아이콘, 피드백, 설명, 이전 경험을 근거로 시스템을 이해한다.
* **맥락:** 제품 사용성, 인터랙션 디자인, UX 설계, 오류 예방, 학습 가능성에서 핵심 개념이다.

## 작동 방식

디자이너는 제품이 어떻게 작동하기를 바라는지에 대한 설계 모델을 갖고 있다. 그러나 사용자는 그 설계 모델을 직접 보지 못한다. 사용자가 실제로 접하는 것은 화면, 물리적 형태, 조작부, 안내 문구, 피드백, 오류 메시지 같은 시스템 이미지다. 사용자는 이 단서를 조합해 자기만의 개념 모델을 만든다.

좋은 디자인은 디자이너의 설계 모델, 시스템 이미지, 사용자의 개념 모델이 서로 가깝게 맞아떨어지도록 만든다. 사용자가 "이 버튼을 누르면 이런 일이 일어날 것"이라고 예상하고, 실제 결과가 그 예상과 일치하면 시스템을 이해했다고 느낀다. 반대로 단서가 불분명하면 사용자는 잘못된 모델을 만들고 반복적으로 실수한다.

* **메커니즘:** 시스템 이미지 노출 -> 사용자 해석 -> 개념 모델 형성 -> 행동 예측 -> 피드백으로 수정.
* **구체적 예시:** 저장 아이콘, 진행 상태 표시, 비활성 버튼, 권한 안내는 모두 사용자의 개념 모델을 형성한다.
* **연계 프로세스:** 설계 모델 정의 -> 사용자에게 보이는 단서 설계 -> 사용 테스트 -> 오해 지점 수정.

## 실무적 의미

개념 모델은 사용성의 핵심이다. 사용자는 시스템의 실제 기술 구조를 몰라도 된다. 대신 자신이 어떤 행동을 할 수 있고, 그 행동이 어떤 결과를 낳으며, 현재 시스템이 어떤 상태인지 이해할 수 있어야 한다.

복잡한 서비스일수록 시스템 이미지는 더 중요해진다. 예를 들어 권한 설정, 추천 알고리즘, 장바구니, 구독 상태, 동기화 상태처럼 보이지 않는 구조는 사용자가 오해하기 쉽다. 이때 상태 표시, 피드백, 설명 문구, 단계적 안내가 개념 모델을 안정화한다.

* **안정성:** 사용자의 예측과 실제 결과가 일치하도록 피드백을 제공한다.
* **측정 가능성:** 첫 사용 성공률, 오류율, 재시도 횟수, 도움말 의존도를 본다.
* **데이터 기준:** 사용자가 설명하는 시스템 작동 방식과 실제 작동 방식의 차이를 조사한다.

## 주의할 점

디자이너는 자신의 설계 모델을 사용자가 당연히 이해한다고 착각하기 쉽다. 그러나 사용자는 코드 구조나 조직 내부 용어가 아니라 화면에 드러난 단서를 기준으로 생각한다. 따라서 내부 모델을 그대로 노출하는 것이 아니라 사용자의 과업에 맞는 설명 구조로 번역해야 한다.

개념 모델은 멘탈 모델과 가깝지만 완전히 같지는 않다. 멘탈 모델은 사용자가 실제로 가진 이해 구조이고, 개념 모델은 제품이 사용자에게 제공해야 할 설명 구조에 더 가깝다. 좋은 디자인은 이 둘의 차이를 줄이는 작업이다.

* **관점의 한계:** 사용자의 개념 모델은 경험, 문화, 숙련도에 따라 다르다.
* **상관관계 vs 인과관계:** 오류가 많다고 해서 기능이 복잡한 것만이 원인은 아니다. 시스템 이미지가 잘못된 모델을 유도했을 수 있다.
