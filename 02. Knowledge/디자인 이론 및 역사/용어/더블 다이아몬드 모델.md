# 더블 다이아몬드 모델

## 핵심 정의

> 더블 다이아몬드 모델은 디자인 문제 해결에서 문제를 찾는 과정과 해결책을 만드는 과정을 각각 발산과 수렴의 흐름으로 설명하는 모델이다.

* **본질:** 좋은 해결책은 곧바로 아이디어를 내는 것이 아니라, 먼저 올바른 문제를 찾고 다시 적절한 해결책을 좁히는 과정에서 나온다.
* **맥락:** 디자인 사고, 서비스 디자인, UX 리서치, 제품 기획, 혁신 프로젝트에서 널리 사용된다.

## 작동 방식

더블 다이아몬드는 두 개의 다이아몬드로 구성된다. 첫 번째 다이아몬드는 문제 공간을 다룬다. 처음에는 리서치와 관찰을 통해 문제를 넓게 탐색하고, 이후 핵심 문제를 정의하며 수렴한다. 두 번째 다이아몬드는 해결 공간을 다룬다. 여러 해결 아이디어를 발산한 뒤, 프로토타입과 테스트를 통해 실행 가능한 해결책으로 좁힌다.

이 모델의 핵심은 발산과 수렴을 분리해서 생각하는 데 있다. 발산 단계에서는 가능한 한 넓게 보고, 수렴 단계에서는 기준을 세워 선택한다. 두 사고 모드를 섞으면 너무 빨리 결론을 내리거나, 반대로 선택하지 못하고 아이디어만 늘어나는 문제가 생긴다.

* **메커니즘:** 문제 발산 -> 문제 수렴 -> 해결 발산 -> 해결 수렴.
* **구체적 예시:** 고객 불만을 넓게 조사한 뒤 핵심 페인포인트를 정의하고, 여러 해결안을 실험한 뒤 하나를 선택한다.
* **연계 프로세스:** 발견, 정의, 개발, 전달의 네 단계로 실행된다.

## 실무적 의미

프로젝트 실패의 많은 원인은 아이디어 부족이 아니라 문제 정의의 실패에서 나온다. 더블 다이아몬드 모델은 팀이 너무 빨리 해결책으로 뛰어드는 것을 막고, 리서치와 문제 정의에 충분한 시간을 쓰게 만든다.

또한 이 모델은 팀 커뮤니케이션에 유용하다. 지금 우리가 문제를 넓히는 중인지, 좁히는 중인지, 아이디어를 늘리는 중인지, 실행안을 고르는 중인지 명확해지면 회의와 의사결정의 성격이 달라진다.

* **안정성:** 각 단계의 목적과 산출물을 혼동하지 않아야 한다.
* **측정 가능성:** 문제 정의의 명확성, 아이디어 다양성, 프로토타입 검증 결과를 본다.
* **데이터 기준:** 리서치 근거, 사용자 피드백, 실험 결과를 단계별 판단 근거로 남긴다.

## 주의할 점

더블 다이아몬드는 선형 체크리스트가 아니다. 실제 프로젝트에서는 테스트 결과에 따라 문제 정의로 돌아가거나, 해결안을 다시 발산해야 할 수 있다. 모델을 너무 기계적으로 따르면 현장의 학습을 반영하지 못한다.

또한 발산이 단순히 아이디어를 많이 내는 시간은 아니다. 문제 발산에서는 실제 사용자 맥락을 넓게 이해해야 하고, 해결 발산에서는 문제 정의와 연결된 가능성을 탐색해야 한다.

* **관점의 한계:** 복잡한 조직 문제를 네 단계로 완전히 설명할 수는 없다.
* **상관관계 vs 인과관계:** 프로세스를 따랐다고 해서 좋은 결과가 보장되는 것은 아니다. 각 단계의 판단 품질이 중요하다.
