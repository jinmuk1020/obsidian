# 공감 (Empathy)

## 핵심 정의

> 공감은 사용자의 관점에서 행동, 감정, 불편, 맥락을 이해하려는 디자인 사고의 핵심 태도이자 조사 방식이다.

* **본질:** 사용자가 말하는 요구뿐 아니라 스스로 설명하지 못하는 잠재적 필요와 사용 맥락을 이해하는 과정이다.
* **맥락:** 디자인 사고, 사용자 중심 디자인, 서비스 디자인, UX 리서치에서 문제 발견의 출발점이 된다.

## 작동 방식

공감은 단순한 친절이나 동정이 아니다. 디자이너가 자신의 가정과 내부 관점을 잠시 내려놓고, 사용자가 실제로 어떤 상황에서 어떤 행동을 하는지 관찰하고 해석하는 과정이다. 인터뷰, 현장 관찰, 맥락 조사, 사용성 테스트, 다이어리 스터디 같은 방법이 공감을 구체화한다.

예를 들어 어린이가 칫솔을 정확히 쥐지 못하는 모습을 관찰하면 문제는 "작은 칫솔이 필요하다"가 아니라 "잡기 쉽고 힘 조절이 쉬운 형태가 필요하다"로 바뀔 수 있다. 사용자가 말한 요구와 실제 행동을 함께 볼 때 더 깊은 문제 정의가 가능해진다.

* **메커니즘:** 사용자 맥락 관찰 -> 말과 행동의 차이 발견 -> 숨은 욕구 해석 -> 문제 재정의.
* **구체적 예시:** 고객센터 문의를 분석할 때 불만 문구뿐 아니라 문의 전 사용자가 거친 절차를 함께 본다.
* **연계 프로세스:** 공감 조사 -> 인사이트 도출 -> 문제 정의 -> 아이디어 발산 -> 프로토타입 검증.

## 실무적 의미

공감은 좋은 아이디어를 떠올리기 위한 감성적 단계가 아니라, 문제를 제대로 정의하기 위한 근거 수집 과정이다. 조직 내부에서는 당연해 보이는 기능이나 절차가 사용자에게는 불편, 불안, 혼란으로 경험될 수 있다.

공감이 충분하지 않으면 이후의 아이디어와 프로토타입은 공급자 중심 추측에 머물 가능성이 높다. 반대로 공감이 잘 이루어지면 제품의 기능보다 사용자의 실제 과업, 제약, 감정 상태를 중심으로 해결책을 찾게 된다.

* **안정성:** 한두 명의 인상적인 사례를 전체 사용자로 일반화하지 않는다.
* **측정 가능성:** 관찰된 행동, 반복되는 표현, 사용 맥락, 실패 지점을 기록한다.
* **데이터 기준:** 인터뷰 발화와 실제 행동 데이터를 함께 비교한다.

## 주의할 점

공감은 사용자의 말을 그대로 믿는 것만으로는 충분하지 않다. 사람은 자신의 행동 이유를 정확히 설명하지 못할 수 있고, 조사 상황에서는 사회적으로 바람직한 답을 할 수도 있다. 따라서 말, 행동, 맥락, 데이터가 서로 어떻게 맞거나 어긋나는지 함께 봐야 한다.

또한 공감은 디자이너의 해석을 포함한다. 관찰한 사실과 해석을 구분하고, 다양한 사용자 집단을 통해 반복 확인해야 한다.

* **관점의 한계:** 공감은 사용자를 대신해 모든 결정을 내려주는 면허가 아니다.
* **상관관계 vs 인과관계:** 사용자가 불편을 말한 지점이 실제 원인인지, 더 앞선 단계의 문제가 누적된 결과인지 확인해야 한다.
