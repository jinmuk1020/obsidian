# 대응(Mapping)과 피드백(Feedback)

## 핵심 정의

> 대응은 조작 장치와 결과 사이의 관계를 사용자가 이해할 수 있게 만드는 원리이고, 피드백은 사용자의 행동 결과를 시스템이 즉시 알려주는 원리다.

* **본질:** 사용자는 무엇을 조작해야 하는지, 조작하면 무엇이 일어났는지 알아야 시스템을 신뢰할 수 있다.
* **맥락:** 인터랙션 디자인, 제품 사용성, 기기 조작, UI, 공공시설, 안전 설계에서 중요하다.

## 작동 방식

대응은 컨트롤과 결과 사이의 관계를 직관적으로 연결한다. 네 개의 가스레인지 화구와 네 개의 손잡이가 같은 공간 구조로 배치되어 있다면 사용자는 어떤 손잡이가 어떤 화구를 조절하는지 쉽게 이해한다. 반대로 대응이 어긋나면 사용자는 매번 추측해야 한다.

피드백은 사용자가 행동한 뒤 시스템 상태가 어떻게 바뀌었는지 알려준다. 버튼을 눌렀을 때 소리, 진동, 색 변화, 진행 표시, 완료 메시지가 없다면 사용자는 행동이 전달되었는지 확신할 수 없다.

* **메커니즘:** 조작 가능성 인식 -> 행동 실행 -> 피드백 확인 -> 다음 행동 결정.
* **구체적 예시:** 볼륨 슬라이더의 위치와 소리 크기, 엘리베이터 버튼의 점등, 저장 완료 메시지.
* **연계 프로세스:** 조작 대상 정의 -> 자연스러운 대응 설계 -> 행동 결과 피드백 -> 사용성 테스트.

## 실무적 의미

대응과 피드백은 사용자의 인지 부담을 줄인다. 사용자는 매뉴얼을 읽지 않고도 조작 결과를 예측하고, 피드백을 통해 자신의 행동이 맞았는지 확인한다. 이는 실행의 간극과 평가의 간극을 줄이는 핵심 원리다.

디지털 제품에서는 피드백의 시간도 중요하다. 반응이 너무 늦으면 사용자는 여러 번 클릭하거나 오류가 발생했다고 느낀다. 반응이 빠르더라도 무엇이 바뀌었는지 알 수 없으면 피드백으로서 충분하지 않다.

* **안정성:** 잘못된 조작이 위험으로 이어지는 영역에서는 대응과 피드백이 특히 명확해야 한다.
* **측정 가능성:** 오조작률, 재시도 횟수, 완료 시간, 사용자 확신도를 확인한다.
* **데이터 기준:** 실제 사용자가 어떤 조작을 예상하고 어떤 결과를 놓치는지 관찰한다.

## 주의할 점

피드백은 많을수록 좋은 것이 아니다. 지나친 알림, 소리, 애니메이션은 오히려 방해가 된다. 중요한 것은 사용자의 다음 행동에 필요한 정보를 적절한 시점에 제공하는 것이다.

대응 역시 문화와 경험에 영향을 받는다. 어떤 사용자는 특정 아이콘이나 방향을 익숙하게 느끼지만, 다른 사용자는 다르게 해석할 수 있다.

* **관점의 한계:** 직관적이라는 말은 사용자 집단과 맥락에 따라 달라진다.
* **상관관계 vs 인과관계:** 사용자가 실수했다고 해서 사용자의 부주의만 원인인 것은 아니다. 대응과 피드백이 부족했을 수 있다.
