# 순서도

## 핵심 정의

순서도는 절차, 판단, 입력과 출력, 반복 흐름을 표준 기호와 화살표로 표현하는 도식이다. 복잡한 업무나 프로그램 로직을 문장으로만 설명하지 않고, 단계별 흐름으로 보여 주기 때문에 과정의 누락, 중복, 병목, 조건 분기를 쉽게 발견할 수 있다.

핵심은 "무엇을 어떤 순서로 처리하는가"를 눈에 보이는 구조로 바꾸는 것이다.

## 작동 방식

순서도는 시작점에서 출발해 처리 단계, 판단 조건, 입력과 출력, 반복 구간을 화살표로 연결한다. 각 기호는 흐름 안에서 다른 역할을 맡는다.

- 시작/종료 기호는 프로세스의 출발점과 끝점을 표시한다.
- 처리 기호는 계산, 작업, 상태 변경처럼 실제로 수행되는 단계를 나타낸다.
- 판단 기호는 예/아니오, 참/거짓, 조건 충족/미충족에 따라 흐름이 갈라지는 지점을 표시한다.
- 입력/출력 기호는 사용자 입력, 데이터 수집, 결과 표시처럼 외부와 정보를 주고받는 단계를 나타낸다.
- 화살표는 단계 사이의 실행 순서와 방향을 보여 준다.

이 구조를 통해 순서도는 절차 구조, 선택 구조, 반복 구조를 표현한다. 절차 구조는 단계가 순서대로 이어지는 흐름이고, 선택 구조는 조건에 따라 다른 경로로 갈라지는 흐름이며, 반복 구조는 특정 조건이 끝날 때까지 같은 절차를 되풀이하는 흐름이다.

## 실무적 의미

기획에서 순서도는 기능의 작동 흐름, 사용자 동선, 업무 절차, 의사결정 규칙을 명확하게 만드는 데 쓰인다. 예를 들어 회원가입 과정, 결제 실패 처리, 게임 튜토리얼 진행, 고객 상담 프로세스는 모두 순서도로 표현할 수 있다.

게임 디자인에서는 플레이어가 어떤 화면을 보고, 어떤 선택을 하며, 선택 결과가 어떤 상태 변화로 이어지는지 설명하는 데 유용하다. UI 흐름, 퀘스트 진행, 보상 지급, 예외 처리처럼 조건과 반복이 많은 구조를 설계할 때 특히 효과적이다.

품질 관리와 프로세스 개선에서도 순서도는 중요하다. [[총체적 품질경영 (TQM)]]이나 [[6시그마 (6 Sigma)]]에서는 현재 업무 흐름을 시각화해 오류가 발생하는 지점, 대기 시간, 중복 작업, 책임 불명확 구간을 찾는다.

## 주의할 점

좋은 순서도는 모든 세부사항을 한 장에 몰아넣지 않는다. 너무 많은 예외와 세부 조건을 넣으면 오히려 읽기 어려워진다. 먼저 핵심 흐름을 그리고, 필요한 경우 하위 순서도로 세부 절차를 분리하는 편이 낫다.

또한 순서도는 실제 실행 흐름을 보여 주어야 한다. 이상적인 절차만 그리면 문제를 숨기게 된다. 현장에서 실제로 누가 무엇을 입력하고, 어떤 조건에서 멈추며, 어떤 예외가 발생하는지 확인해야 한다.
