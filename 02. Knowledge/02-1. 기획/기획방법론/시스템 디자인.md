
system design
게임의 데이터들이 어떻게 논리적인 규칙으로 동작할지 정의하고, 이를 통해 플레이어가 경험할 구체적인 흐름을 설계하는 과정. 흔히 게임 규칙을 위한 규칙을 만드는 작업으로 불리며, 디자이너의 의도가 실제 게임플레이로 변환되는 핵심적인 설계 단계

시스템 디자인의 핵심 비유:호두과자 기계
시스템:앙금을 넣고, 반죽을 붓고, 틀을 뒤집어 과자를 구워내는 기계의 구조와 틀. 이는 게임 내에서 변하지 않는 논리적 규칙을 의미
[[데이터]]:기계 안에 들어가는 반죽과 앙금. 게임 내에서 가변적인 수치를 말함

시스템과 데이터의 분리
현대 게임 디자인에서는 시스템과 데이터를 명확히 분리하여 설계하는 것이 매우 중요
유연성 확보:시스템 구조를 한 번 잘 만들어두면,프로그래머의 도움 없이도 디자이너가 데이터 테이블의 수치만 수정하여 게임의 난이도나 밸런스를 조절할 수 있음.
디자인 의도 적용:예를 들어 덧셈 게임을 만들 때,너무 쉬운 문제는 제외한다는 등의 세부적인 의도를 데이터 제어를 통해 효율적으로 구현할 수 있음.
전투 시스템 사례:전투 공식을 항상 동일하지만,몬스터의 종류별 능력치에 따라 플레이어가 느끼는 긴장감이 달라짐

시스템 디자인의 프로세스
시스템 디자인은 다음과 같은 단계적 과정을 거쳐 게임에 구현됨.
시스템 디자인:게임의 동작 원리와 논리적 판정 기준을 설계
시스템 구현:설계된 논리 구조를 실제 프로그래밍 코드로 변환
데이터 입력:디자이너가 원하는 수치나 속성을 데이터 테이블 형식으로 입력
게임 플레이:입력된 데이터가 시스템이라는 틀 안에서 돌아가며 최종적인 게임 경험이 완성됨.

성공적인 시스템 설계를 위한 원칙
명확한 기준 수립:시스템을 설계할 때는 예외 상황 없이 모든 판정이 이루어질 수 있도록 논리적인 기준이 정교해야 함
숫자에 익숙해지기:시스템은 결국 수치로 처리되므로,확률과 공식 등 정량적인 데이터 처리에 능숙해야 함
연계성 고려:개별 시스템이 다른 시스템과 어떻게 상호작용하는지 전체적인 맥락에서 파악해야 함
시스템적 사고:단편적인 문제 해결이 아니라, 시스템을 구성하는 다양한 요소들의 상호작용이 전체 시스템에 어떤 영향을 미치는지 분석하여 최적화해야 함
