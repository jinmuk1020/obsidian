# 가상환경

## 핵심 정의
가상환경은 프로젝트별로 파이썬 실행 환경과 패키지 의존성을 분리해 관리하는 작업 공간이다. 같은 컴퓨터 안에서도 프로젝트마다 서로 다른 라이브러리 버전과 설정을 사용할 수 있게 해준다.

데이터 분석과 머신러닝 프로젝트는 패키지 버전에 민감하다. 가상환경을 사용하면 한 프로젝트에서 필요한 설정이 다른 프로젝트를 망가뜨리지 않고, 나중에 같은 분석을 다시 실행할 가능성도 높아진다.

## 작동 방식
가상환경을 만들면 별도의 파이썬 인터프리터 경로와 패키지 설치 위치가 생긴다. 환경을 활성화한 상태에서 설치한 패키지는 해당 환경 안에만 적용된다. 프로젝트는 `requirements.txt`, `environment.yml`, `pyproject.toml` 같은 파일로 의존성을 기록해 재현성을 확보한다.

conda 환경은 파이썬 패키지뿐 아니라 일부 시스템 라이브러리까지 함께 관리할 수 있어 데이터 과학 분야에서 자주 쓰인다. 반면 `venv`나 `virtualenv`는 파이썬 기본 생태계에 가까운 가벼운 방식이다.

## 실무적 의미
노트북, 전처리 코드, 모델 학습 파이프라인은 특정 패키지 버전에 따라 결과가 달라질 수 있다. 가상환경은 분석 결과를 다른 장비나 서버에서 다시 실행할 때 가장 먼저 확인해야 하는 기반이다.

팀 작업에서는 환경 파일을 저장소에 포함시켜야 한다. 그래야 새 구성원이 같은 환경을 빠르게 만들 수 있고, 운영 서버나 실험 서버에서도 동일한 조건을 재현할 수 있다.

## 주의할 점
가상환경을 만들기만 하고 의존성 파일을 관리하지 않으면 재현성은 확보되지 않는다. 반대로 모든 패키지를 기본 환경에 설치하면 충돌이 누적되어 어떤 프로젝트가 어떤 버전에 의존하는지 알기 어려워진다.

conda와 pip를 함께 사용할 때는 설치 순서와 채널을 신중히 관리해야 한다. 가능하면 프로젝트별 환경을 작게 유지하고, 불필요한 패키지를 기본 환경에 몰아넣지 않는 편이 좋다.
