# 데이터 독립성 (Data Independence)

## 핵심 정의

데이터 독립성은 게임의 규칙을 실행하는 로직과 조정 가능한 데이터를 분리하는 설계 원칙이다. 코드가 “어떻게 처리할지”를 담당한다면, 데이터는 “무엇을 얼마만큼 적용할지”를 담당한다.

예를 들어 무기의 피해량, 몬스터의 체력, 퀘스트 보상, 상점 가격, 스폰 확률이 코드 안에 박혀 있지 않고 별도의 데이터로 관리된다면 디자이너는 코드를 고치지 않고도 밸런스를 조정할 수 있다.

## 작동 방식

데이터 독립성은 보통 [[데이터 테이블 (DataTable)]], 설정 파일, 데이터베이스, 스크립터블 오브젝트, 에셋 메타데이터 같은 형태로 구현된다. 게임 로직은 이 데이터를 읽어 동일한 규칙으로 처리하고, 데이터 변경은 결과의 수치와 내용을 바꾼다.

이 구조에서는 새로운 아이템을 추가할 때 매번 새로운 코드를 작성하지 않아도 된다. 같은 아이템 처리 규칙을 사용하되, 이름, 가격, 효과, 쿨다운, 아이콘, 희귀도 같은 값만 데이터로 정의하면 된다.

## 설계적 의미

데이터 독립성은 반복 조정이 많은 게임 개발에서 중요하다. 밸런싱, 라이브 운영, A/B 테스트, 콘텐츠 확장, 지역화, 난이도 조정은 모두 데이터가 로직에서 분리되어 있을 때 훨씬 안전하고 빠르게 이루어진다.

또한 데이터 독립성은 [[모듈화 (Modularization)]]와 연결된다. 기능이 명확한 규칙 단위로 나뉘고 데이터가 외부에서 주입되면, 시스템은 재사용 가능해지고 변경의 범위도 좁아진다.

## 주의할 점

모든 것을 데이터로 빼는 것이 항상 좋은 것은 아니다. 규칙 자체가 자주 바뀌거나 데이터 간 의존성이 지나치게 복잡해지면, 데이터 테이블은 설계 도구가 아니라 숨겨진 코드처럼 변한다. 이 경우 디버깅은 더 어려워지고, 데이터 작성자가 시스템의 실제 동작을 이해하기 힘들어진다.

좋은 데이터 독립성은 로직과 데이터의 경계를 분명히 한다. 자주 조정해야 하는 값은 데이터로 두고, 시스템의 핵심 규칙은 코드나 명확한 설계 구조 안에 둔다.
