# 데이터 테이블 (DataTable)

## 핵심 정의

데이터 테이블은 게임 시스템이 사용할 값과 속성을 행과 열로 정리한 구조다. 코드가 규칙을 실행한다면, 데이터 테이블은 그 규칙에 들어갈 구체적인 수치와 콘텐츠를 제공한다.

예를 들어 몬스터의 체력과 공격력, 아이템 가격, 퀘스트 조건, 보상량, 레벨별 경험치 요구량, 스킬 쿨다운은 데이터 테이블로 관리할 수 있다. 이렇게 하면 코드를 매번 수정하지 않고도 게임의 세부 감각을 조정할 수 있다.

## 작동 방식

데이터 테이블은 보통 각 행에 고유 ID를 두고, 열에는 이름, 유형, 수치, 조건, 참조 대상 같은 속성을 둔다. 시스템은 ID를 통해 특정 데이터를 불러오고, 그 값을 규칙에 대입해 결과를 만든다.

예를 들어 전투 시스템은 몬스터 테이블의 체력과 공격력을 읽고, 퀘스트 시스템은 퀘스트 테이블의 시작 조건과 보상을 읽는다. 규칙은 코드에 남아 있고, 조정 가능한 값은 테이블에 남는다. 이 분리가 [[데이터 독립성 (Data Independence)]]의 실무적 기반이 된다.

## 설계적 의미

데이터 테이블은 밸런싱과 콘텐츠 생산의 핵심 도구다. 디자이너는 여러 값을 비교하면서 난이도 곡선, 보상 속도, 경제 흐름, 성장 리듬을 조정할 수 있다. 라이브 서비스 게임에서는 업데이트와 이벤트마다 값이 계속 바뀌기 때문에 데이터 테이블의 구조가 운영 효율을 좌우한다.

좋은 데이터 테이블은 읽기 쉽고, 의도가 분명하며, 참조 관계가 안정적이다. 같은 의미의 값은 같은 단위와 명명 규칙을 사용해야 하고, ID는 바뀌지 않아야 한다. 테이블이 커질수록 “값을 넣는 표”가 아니라 시스템 설계 문서의 일부가 된다.

## 주의할 점

모든 규칙을 데이터 테이블로 밀어 넣으면 테이블이 숨겨진 코드처럼 변한다. 조건문과 예외가 지나치게 많아지면 디자이너도 프로그래머도 실제 동작을 추적하기 어려워진다. 자주 조정할 값은 테이블에 두고, 시스템의 핵심 규칙은 명확한 코드와 설계 구조에 두는 편이 안정적이다.

또한 테이블의 빈 값, 중복 ID, 잘못된 참조는 런타임 오류나 이상한 밸런스로 이어질 수 있다. 데이터 검증 규칙과 리뷰 절차가 함께 필요하다.
