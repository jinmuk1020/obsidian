본 보고서는 토비아스 호이스너(Tobias Heussner) 외 3인이 저술한 **《The Game Narrative Toolbox (Second Edition)》** 소스 내용을 바탕으로, 게임 내 텍스트의 유연성과 플레이어 맞춤형 경험을 가능하게 하는 기술적 장치인 **토큰 / 스트링 (Tokens / Strings)** 개념을 정리한 것입니다.

# 토큰 / 스트링 (Tokens / Strings)

## 한 문장 정의
토큰(또는 스트링)은 게임 텍스트 내에 삽입되는 **작은 코드 조각**으로, 플레이어가 자신의 캐릭터에 대해 선택한 정보(이름, 성별, 소속 등)를 실시간으로 참조하여 해당 위치에 적절한 단어를 불러오는 **가변적 자리 표시자(Placeholders)**입니다 [1, 2].

## 상세 정의
* **기술적 변수:** 고정된 단어 대신 사용되는 [[데이터|데이터]] 값으로, 보통 `@player_name`, `_player_name`, 또는 `[player_name_here]`와 같은 특수한 형태의 기호로 작성됩니다 [1].
* **동적 텍스트 생성:** 작가가 하나의 문장을 작성하더라도, 시스템은 플레이어의 데이터베이스를 조회하여 해당 위치에 실제 플레이어의 이름이나 칭호 등을 대입해 맞춤형 대사를 출력합니다 [1, 3].
* **몰입의 매개체:** 고정된 주인공이 없는 게임에서 플레이어가 자신의 정체성을 게임 내 세계관과 연결하도록 돕는 핵심적인 내러티브 도구입니다 [3].

## 문서 안에서의 맥락
본 소스의 **제7장 '대화(Dialogue)'** 섹션 중 '소셜 및 모바일 게임의 대화' 파트에서 중요하게 다뤄집니다. 특히 주인공이 고정되어 있지 않은 MMO(대규모 다중 접속 온라인 게임)나 소셜 RPG에서 플레이어의 선택(성별, 종족, 배경 등)을 대화 속에 자연스럽게 녹여내기 위한 필수적인 기술 요소로 소개됩니다 [1, 4, 5].

## 작동 메커니즘
1. **초기 설정:** 게임 설계 초기 단계에서 기술 담당자(Technical Designer)가 어떤 정보(이름, 성별, 소속 가문 등)를 토큰화할지 정의합니다 [1].
2. **문장 작성:** 작가는 대사를 쓸 때 고정된 단어 대신 정의된 토큰을 섞어서 작성합니다. (예: "안녕하세요, **@address @player_name**님.") [1, 3].
3. **런타임 치환:** 플레이어가 게임을 플레이하는 순간, 엔진은 해당 토큰을 플레이어의 실제 데이터로 바꿉니다.
 * 플레이어가 남성(Tobias)이고 '라니스터' 가문 소속이라면: "**My lord Tobias**, the **Lannisters** want you..."라고 출력됩니다 [3].

## 설계/비즈니스상 중요도
* **개인화된 경험 제공:** 플레이어가 자신이 만든 캐릭터가 세계관 내에서 실제로 인정받고 상호작용하고 있다는 느낌을 강하게 줍니다 [3].
* **콘텐츠 효율성:** 수천 명의 서로 다른 배경을 가진 캐릭터들에 대해 일일이 별도의 대사를 쓸 필요 없이, 토큰을 활용한 하나의 문장만으로도 수만 가지의 조합에 대응할 수 있어 제작 비용을 절감합니다 [570, 추정].
* **장르적 필수성:** 다양한 인종과 배경을 가진 영웅들이 등장하는 MMO 장르에서는 토큰 [[시스템 (System)|시스템]] 없이는 정상적인 대화 전달이 거의 불가능합니다 [5].

## 구체 사례
* **《왕좌의 게임: 어센트 (Game of Thrones: Ascent)》:** 플레이어가 남성/여성을 선택하고, 칠왕국 중 어느 곳에 거주하며 어느 가문에 충성할지를 결정할 수 있었던 게임입니다. 개발팀은 다음과 같은 토큰 조합을 사용했습니다: `"@address @player_name, the @fealty_plural want you to return to @fealty_city before @fealty_region gets invaded!"` [1, 3].
* **MMO 일반:** 영웅들의 성별, 종족, 배경이 매우 다양하기 때문에 거의 모든 MMO 대화 작성에는 토큰이 필수적으로 사용됩니다 [5].

## 실무 적용 방법
* **기술 팀과의 협업:** 토큰은 작가 마음대로 정하는 것이 아니라, 게임 엔진이 인식할 수 있도록 기술진과 미리 약속된 형식을 사용해야 합니다 [1].
* **문장 구조 설계:** 토큰이 들어갈 위치를 고려하여 문장을 구성하십시오. 토큰에 대입될 단어의 길이에 따라 UI(사용자 인터페이스) 상에서 글자가 잘릴 수 있으므로 여유 공간을 확보해야 합니다 [570, 추정].
* **전용 템플릿 제작:** 대화 상자 내에 정보가 항상 같은 위치에 나타나도록 토큰 위치를 고정한 템플릿을 활용하면 플레이어가 정보를 더 빨리 찾을 수 있습니다 [6].

## 흔한 오해와 주의점
* **번역 및 현지화의 함정:** 영어는 성별에 따른 문장 구조 변화가 크지 않지만, 많은 외국어는 성별이나 수(단수/복수)에 따라 동사나 형용사의 어미가 변합니다. 이 경우 단순한 단어 치환(토큰 사용)만으로는 문법적으로 틀린 문장이 생성될 수 있습니다 [5].
* **글자 수 제한 초과:** 토큰이 실제 단어로 치환되었을 때, 문장의 전체 길이가 시스템이 허용하는 글자 수 제한을 초과하여 오류를 일으키거나 레이아웃을 망가뜨릴 수 있으므로 주의해야 합니다 [5].

## 관련 개념
- **[[시스템적 대화 (Systemic Dialogue)|대화 (Dialogue)]]**: 토큰이 실제로 구현되고 활용되는 게임의 언어적 전달 수단 [7].
- **[[현지화 (Localization)]]**: 토큰 시스템이 가장 큰 기술적 도전에 직면하게 되는 언어 변환 공정 [8, 9].
- **[[플레이어 에이전시 (Player Agency)]]**: 토큰을 통한 개인화된 부름을 통해 강화되는 플레이어의 주도권과 연결감 [10].
- **[[변수 (Variables)]]**: 토큰이 참조하는 데이터의 근간이 되는 논리적 값 [11].
