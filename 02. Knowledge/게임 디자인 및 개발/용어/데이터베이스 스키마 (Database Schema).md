# 데이터베이스 스키마 (Database Schema)

## 핵심 정의

데이터베이스 스키마는 데이터베이스 안에 어떤 데이터가 어떤 구조와 관계로 저장되는지를 정의한 설계도다. 테이블, 필드, 자료형, 기본 키, 외래 키, 제약 조건, 관계 규칙이 스키마에 포함된다.

게임 개발에서는 계정, 캐릭터, 인벤토리, 아이템, 퀘스트 상태, 결제 기록, 로그 데이터처럼 지속적으로 저장해야 하는 정보를 어떤 구조로 관리할지 정하는 기준이 된다.

## 작동 방식

스키마는 데이터의 형태와 관계를 고정한다. 예를 들어 캐릭터 테이블은 캐릭터 ID, 계정 ID, 이름, 레벨, 직업 같은 필드를 가질 수 있고, 인벤토리 테이블은 아이템 ID와 소유자 캐릭터 ID를 통해 캐릭터와 연결될 수 있다.

이 구조가 명확하면 서버와 클라이언트, 운영 도구, 분석 시스템이 같은 데이터 의미를 공유할 수 있다. 반대로 스키마가 불분명하면 같은 값이 여러 곳에 중복 저장되거나, 참조가 깨지거나, 업데이트 과정에서 데이터 무결성이 손상될 수 있다.

## 설계적 의미

데이터베이스 스키마는 라이브 게임의 안정성과 직결된다. 출시 이후에도 플레이어 데이터는 계속 누적되기 때문에, 스키마 변경은 단순한 수정이 아니라 기존 데이터를 어떻게 보존하고 변환할지까지 포함하는 운영 문제다.

스키마 설계는 [[관계 DBMS (Relational DBMS)]]의 개념과 연결된다. 특히 기본 키와 외래 키를 통해 데이터 사이의 관계를 명확히 하면 캐릭터, 아이템, 퀘스트, 거래 기록 같은 복잡한 데이터를 일관되게 관리할 수 있다.

## 주의할 점

스키마를 너무 느슨하게 만들면 빠른 변경은 쉬워 보이지만 데이터의 의미가 흐려진다. 반대로 너무 일찍 세밀하게 고정하면 게임 설계 변경에 취약해진다. 초기에는 변화 가능성을 열어 두되, 운영 데이터의 핵심 관계는 명확히 정의해야 한다.

또한 스키마 변경에는 마이그레이션 계획이 필요하다. 이미 저장된 플레이어 데이터가 새 구조와 충돌하지 않도록 변환 규칙, 백업, 롤백 가능성을 함께 고려해야 한다.
