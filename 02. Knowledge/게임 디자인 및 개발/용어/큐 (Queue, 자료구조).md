# 큐 (Queue, 자료구조)

## 한 문장 정의
큐는 항목들을 특정 순서로 추가한 뒤, 먼저 들어온 데이터가 먼저 나가는 **선입선출(FIFO, First In First Out)** 원칙에 따라 데이터를 처리하고 제거하는 자료구조입니다 [1, 2].

## 상세 정의
* **구조적 특징**: 큐는 배열(Array)이나 리스트(List)의 변형된 형태로 볼 수 있으며, 데이터를 한쪽 끝(뒤)에서 넣고 반대쪽 끝(앞)에서 꺼내는 방식입니다 [1, 2].
* **FIFO 원리**: 'First In First Out'의 약자로, 가장 먼저 대기열에 합류한 데이터가 가장 먼저 처리 대상이 된다는 의미입니다 [2].
* **동적 유연성**: 데이터가 고정된 위치에 머무는 것이 아니라, 앞의 데이터가 처리되어 나가면 다음 데이터가 첫 번째 자리를 차지하며 순차적으로 이동하는 흐름을 가집니다 [2].

## 문서 안에서의 맥락
본 소스에서 큐는 **제4장 '랜덤 던전 생성'**의 핵심 알고리즘을 구현하기 위한 도구로 도입됩니다 [3, 4]. 저자는 던전의 '[[필수 경로 (Essential Path)|필수 경로]](Essential path)'를 먼저 생성한 뒤, 이 경로의 각 지점을 방문하여 무작위로 새로운 분기(Random paths)를 뻗어 나가야 하는 복잡한 작업 순서를 관리하기 위해 큐가 필요하다고 설명합니다 [2, 5]. 특히, 중복을 허용하지 않는 [[딕셔너리 (Dictionary, CSharp 자료구조)|딕셔너리]](Dictionary)의 한계를 극복하고, 생성 도중 새로 추가된 지점들까지 빠짐없이 순차적으로 방문하기 위한 목적에서 사용됩니다 [1, 5].

## 작동 메커니즘
던전 생성 알고리즘 내에서 큐는 다음과 같은 단계를 통해 작동합니다:
1. **대기열 삽입**: 이미 생성된 필수 경로상의 모든 좌표점들을 큐의 맨 뒤에 추가(Populate)합니다 [2, 6].
2. **순차적 인출**: 큐의 가장 앞에 있는 좌표(첫 번째 항목)를 꺼내어 처리 프로세스에 투입합니다 [2].
3. **조건부 확장**: 해당 좌표에서 무작위 분기(Branch)가 발생할 경우, 새로 생성된 경로의 좌표점을 다시 큐의 맨 뒤에 추가하여 나중에 처리되도록 예약합니다 [6, 7].
4. **항목 제거**: 처리가 끝난 좌표는 큐에서 즉시 제거되어 다시 방문하지 않도록 합니다 [2, 6].
5. **반복 및 종료**: 큐가 완전히 빌 때까지(더 이상 처리할 경로 지점이 없을 때까지) 이 과정을 반복하며 던전을 완성합니다 [6, 8].

## 설계/비즈니스상 중요도
* **알고리즘의 안정성**: 큐를 사용하면 던전의 모든 지점을 체계적으로 방문할 수 있어, 특정 구역이 누락되거나 처리가 지연되는 문제를 방지합니다 [6].
* **동적 확장성**: 던전 생성 도중 실시간으로 새로운 작업(새 경로 지점)이 추가되더라도 큐의 끝에 붙여넣기만 하면 되므로, 복잡한 재귀 호출 없이도 방대한 미로 구조를 설계할 수 있습니다 [1, 7].
* **자원 효율성**: 처리가 끝난 항목을 즉시 제거하는 FIFO 방식을 통해 메모리 상에서 불필요하게 대기하는 데이터를 최소화합니다 [2, 6].

## 구체 사례
* **은행 대기열 비유**: 큐의 작동 원리를 설명하기 위해 사람들이 은행에서 줄을 서서 자기 차례를 기다리고, 처리가 끝나면 나가는 실생활 사례가 언급됩니다 [2].
* **무작위 경로 분기 관리**: [[필수 경로 (Essential Path)|필수 경로]] 좌표들을 큐에 복사한 뒤, `foreach` 루프를 통해 하나씩 꺼내며 해당 지점에서 방(Chamber)을 만들거나 추가 경로를 생성할지 결정하는 데 사용됩니다 [7, 9, 10].

## 실무 적용 방법
* **리스트를 활용한 구현**: C#의 `List<T>` 클래스는 요소를 끝에 추가하거나 앞 요소를 제거하는 것이 용이하므로, 이를 큐 자료구조로 활용할 수 있습니다 [7].
* **Delegate 기반 처리**: `pathQueue.ForEach(delegate(PathTile tile) { ... });`와 같은 구문을 사용하여 큐 내부의 각 타일을 순차적으로 처리하는 로직을 구축합니다 [9, 11].
* **동적 데이터 전이**: 필수 경로를 담은 [[딕셔너리 (Dictionary, CSharp 자료구조)|딕셔너리]] 데이터를 큐(리스트)로 옮겨 담아 루프를 돌림으로써, 원본 데이터를 보존하면서도 순차적인 확장을 수행합니다 [9].

## 흔한 오해와 주의점
* **딕셔너리와의 혼동**: 딕셔너리는 특정 키를 통한 '빠른 조회'가 목적이지만, 큐는 작업의 '처리 순서'를 보장하는 것이 목적입니다. 던전 생성 시 위치 중복을 막기 위해서는 딕셔너리를, 처리 순서를 관리하기 위해서는 큐를 병행 사용해야 합니다 [1, 5].
* **종료 조건의 중요성**: (추정) 무작위 분기 확률이 너무 높으면 큐에 계속해서 새로운 항목이 추가되어 알고리즘이 끝나지 않을 수 있으므로, 확률 설정이나 그리드 경계 제한을 통해 큐가 비워질 수 있도록 설계해야 합니다 [153, 195, 추정].

## 관련 개념
- **[[FIFO (First In First Out)]]**: 큐의 가장 핵심적인 처리 원칙인 선입선출 방식 [1, 2].
- **[[필수 경로 (Essential Path)]]**: 큐에 가장 먼저 담겨 던전의 뼈대를 형성하는 기초 경로 [2, 12].
- **[[무작위 경로 (Random Path)]]**: 큐를 통해 처리되는 과정에서 확률적으로 파생되는 던전의 확장 요소 [7, 13].
- **[[딕셔너리|딕셔너리 (Dictionary)]]**: 큐와 대조적으로 고유한 위치 값을 저장하고 중복 생성을 막는 데 사용되는 자료구조 [5, 14].
