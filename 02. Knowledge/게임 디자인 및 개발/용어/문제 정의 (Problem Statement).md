# 문제 정의 (Problem Statement)

## 핵심 정의

문제 정의는 해결해야 할 설계 과제와 제약을 명확한 문장으로 정리하는 일이다. 좋은 문제 정의는 무엇을 해결하려는지, 무엇은 해결 대상이 아닌지, 성공을 어떻게 판단할지 구분하게 만든다.

게임 개발에서는 문제 정의가 아이디어보다 먼저 필요하다. 문제가 흐리면 해결책은 많아 보여도 실행 방향이 갈라진다.

## 작동 방식

문제 정의는 목표, 사용자 맥락, 제약, 성공 기준을 포함한다. “재미있는 전투 만들기”보다 “초보자가 5분 안에 회피와 반격의 관계를 이해하게 만들기”가 더 좋은 문제 정의다.

질문형으로 만들면 발상에 도움이 된다. “어떻게 하면 플레이어가 실패를 불공정함이 아니라 학습 기회로 받아들이게 할 수 있을까”처럼 쓰면 해결 방향이 열린다.

## 설계적 의미

문제 정의는 팀의 공통 기준이 된다. 기능 제안, 콘텐츠 추가, UI 변경이 실제 문제를 해결하는지 판단할 수 있다.

또한 문제 정의는 창의성을 제한하는 것이 아니라 집중시킨다. 명확한 제약은 더 좋은 해결책을 찾게 만든다.

## 주의할 점

문제를 해결책처럼 쓰면 안 된다. “튜토리얼 팝업 추가”는 문제 정의가 아니라 해결안이다. 실제 문제는 플레이어가 무엇을 이해하지 못하는지다.

문제 정의가 너무 넓으면 실행 지침이 되지 않고, 너무 좁으면 더 나은 대안을 막는다. 검증 가능한 크기로 잡는 것이 중요하다.
