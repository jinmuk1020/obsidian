# 사용자 경험 테스트 (UX Tests)

사용자 경험 테스트는 대상 플레이어가 게임을 실제로 사용하는 과정을 관찰해, 시스템이 의도한 대로 이해되고 즐겁게 작동하는지 검증하는 절차다.

UX 테스트는 플레이어에게 게임이 좋은지 묻는 설문만이 아니다. 플레이어가 어디서 망설이고, 무엇을 오해하고, 어떤 감정을 느끼며, 어떤 행동을 반복하는지 보는 과정이다.

## 작동 방식

테스트에서는 플레이어에게 특정 과업을 수행하게 하고 완료 시간, 실수, 질문, 이동 경로, 시선, 감정 반응을 관찰한다. 이후 인터뷰나 설문으로 플레이어가 왜 그렇게 행동했는지 확인한다.

게임에서는 조작감, UI, 튜토리얼, 퀘스트 이해, 보상 피드백, 난이도 곡선, 정보 구조가 주요 관찰 대상이 된다. 특히 플레이어가 실패한 이유를 게임 내부에서 이해했는지가 중요하다.

## 설계 의미

UX 테스트는 제작자가 생각한 게임과 플레이어가 실제로 경험한 게임 사이의 차이를 보여준다. 디자이너에게 명백한 구조가 플레이어에게는 보이지 않을 수 있고, 예상하지 못한 행동이 더 자연스러운 해법으로 나타날 수도 있다.

좋은 테스트는 취향 평가보다 설계 가설 검증에 가깝다. 예를 들어 "플레이어가 3분 안에 목표를 이해할 것이다"라는 가설을 세우고 실제 플레이에서 확인한다.

## 테스트 설계 기준

테스트 목표는 좁아야 한다. 전체 게임이 재미있는지를 한 번에 확인하려 하면 결과가 흐려진다. 튜토리얼 이해, 전투 피드백, 퀘스트 안내, UI 탐색처럼 관찰 가능한 질문으로 나누는 것이 좋다.

또한 참가자의 숙련도와 장르 경험을 구분해야 한다. 초보자가 어려워하는 문제와 숙련자가 지루해하는 문제는 다른 설계 판단을 요구한다.

## 주의할 점

테스트 결과를 그대로 기능 목록으로 바꾸면 안 된다. 플레이어가 요구한 해결책보다, 그 요구가 나온 원인을 분석해야 한다. "버튼을 더 크게 해 달라"는 말은 실제로는 정보 우선순위나 시선 흐름 문제일 수 있다.

테스트 진행자의 설명과 개입도 결과를 왜곡할 수 있다. 가능한 한 플레이어가 스스로 이해하고 행동하는 과정을 관찰해야 한다.
